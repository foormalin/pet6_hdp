# Резервное копирование и восстановление

## Состав бэкапа

`make backup` создаёт каталог `backups/<UTC timestamp>/`:

- `database.sql.gz` — консистентный логический dump MariaDB;
- `glpi-files.tar.gz` — конфигурация и файлы volume `/var/glpi`;
- `SHA256SUMS` — контрольные суммы;
- `manifest.txt` — время, проект и имя базы.

Prometheus и Grafana не входят в бэкап: их конфигурация хранится в Git, а исторические метрики не являются бизнес-данными MVP.

## Создание

```bash
make health
make backup
```

После создания перенесите каталог на другой физический носитель. Бэкап на том же диске не защищает от отказа диска.

Проверка:

```bash
cd backups/20261001T120000Z
sha256sum --check SHA256SUMS
```

## Восстановление

```bash
make restore BACKUP=backups/20261001T120000Z
```

Скрипт:

1. проверяет наличие файлов и их SHA-256;
2. показывает имя целевой базы;
3. требует ввести `RESTORE <database>`;
4. останавливает Nginx и GLPI;
5. пересоздаёт базу и загружает dump;
6. заменяет содержимое volume GLPI;
7. запускает сервис и выполняет health check.

Восстановление разрушительно для текущей базы и файлов GLPI. Не выполняйте его без отдельного актуального бэкапа.

## Тест восстановления

Проводите тест не реже одного раза в квартал в отдельном Docker project:

```bash
COMPOSE_PROJECT_NAME=helpdesk_restore HTTP_PORT=18080 GRAFANA_PORT=13000 PROMETHEUS_PORT=19090 docker compose up -d
```

Скопируйте бэкап в тестовый checkout, восстановите его и подтвердите:

- вход в GLPI работает;
- тестовая заявка открывается;
- вложения доступны;
- `make health` завершается без ошибок.

Только проверенный restore подтверждает пригодность бэкапа.
